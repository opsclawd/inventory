### Mandatory Database, Auth & CI Guardrails (`ADR-0005` & `ADR-0006`)

- **Prisma + Supavisor Transaction-Local RLS (`erp_app_user` & `tx.$queryRaw`):** Runtime connections over Supavisor transaction pooling (`?pgbouncer=true` on port `6543`; `DIRECT_URL` on port `5432` for migrations/admin only) MUST execute as least-privilege `erp_app_user` (`NOBYPASSRLS`, `plan_cache_mode = force_custom_plan`) with `ENABLE ROW LEVEL SECURITY` + `FORCE ROW LEVEL SECURITY` across all tables in `shared` (explicitly including `shared.User`), `salvage`, and `cannabis`, plus composite intra-tenant foreign keys (`@@unique([organizationId, id])`). Session-level `SET`, autocommit `set_config`, `$queryRawUnsafe`, `$executeRawUnsafe`, and `tx.$executeRaw` around `SELECT set_config(...)` are strictly banned. All tenant repository operations MUST execute inside `withTenantTransaction(prisma, ctx, fn)` using parameterized **`tx.$queryRaw`** `SELECT set_config(..., true)` followed by an in-transaction `SELECT "shared"."current_org_id"()` assertion verifying an active `OrganizationMembership` (`isActive = true`) via fixed-`search_path` (`SET search_path = ''`) `SECURITY DEFINER` helpers.
- **Trusted Server-Side Identity Context (`@supabase/ssr`):** PostgreSQL session GUCs (`app.current_org_id`, `app.current_user_id`, `app.current_role`) are not self-authenticating claims. Derive `TenantContext` exclusively on the server via `@supabase/ssr` `await supabase.auth.getUser()` (server-side `getSession()` is banned), awaited Next.js 15 `await cookies()` / `await headers()`, and a verified database `OrganizationMembership` (`isActive = true`)—never from unverified client request parameters.
- **Liquidity vs. Revenue & Jurisdiction-Aware Tax (`FIX 05` & `FIX 06`):** Never classify pending eBay payouts (`MARKETPLACE_PAYOUT_PENDING`) or unconfirmed e-Transfers (`BANK_SETTLEMENT_PENDING`) as `SETTLED_ORIGIN_CORP_BANK` or include them in deployable `AvailableWorkingCapital_CAD`. Preserve authoritative marketplace-reported buyer tax (`buyerTaxRemittedByPlatformMinor`) on eBay orders, apply CRA destination place-of-supply rates on direct sales (`RULE-TAX-HST-01`), and require verified tax-invoice evidence (`isFeeTaxInvoiceVerified = true`) before promoting `estimatedPlatformFeeTaxCadMinor` into recoverable `itcReceivableCadMinor`.

### Objective Phase 1A Autonomous Agent Readiness Policy (`ADR-0006` `FIX 08`)

1. **8-Point Machine-Checkable Ticket Readiness Gate:** An issue may be claimed by an autonomous coding agent only when all 8 conditions hold:
   1. Its domain contract (`ARCHITECTURE.md`, `DOMAIN-RULES.md`, `PRD.md`, `GLOSSARY.md`) is stable.
   2. Its scope and explicit non-goals (including phase boundaries) are stated.
   3. All blocking GitHub issue dependencies (`Blocked by`) are closed/merged.
   4. Its required TypeScript/SQL interfaces and exact file ownership list are defined.
   5. Its acceptance criteria are deterministic and assert concrete state/error outcomes.
   6. Its failure, authorization, revocation (`OrganizationMembership.isActive = false`), and cross-tenant security conditions are specified.
   7. Its exact verification commands (`pnpm typecheck`, `pnpm verify:no-stubs`, unit/integration test commands) are defined.
   8. No unresolved foundational architectural, regulatory, or accounting decision must be invented during implementation.
2. **Ticket Size Complexity Budget (`10` Files Default Upper Bound):** Keep each issue within **10 implementation files** by default. Treat this as a complexity budget—never omit required tests or violate Hexagonal module boundaries merely to hit a file count, do not split cohesive atomic work arbitrarily, and document an explicit justification if any ticket ever requires >10 files.
3. **Fail-Closed No-Stub & Composition Gate (`pnpm verify:no-stubs`):** Negated shell `grep` one-liners that can pass when directories are missing or search commands error out are prohibited. Every PR from `Issue #1` onward must pass `pnpm verify:no-stubs` (`node scripts/verify-no-stubs.mjs`), which fails closed (`exit 1`) on missing required directories/files, scan failures, placeholder/stub tokens (`not wired`, `TODO.*compose`, `throw new Error("Not implemented")`), or banned unsafe raw SQL calls (`$queryRawUnsafe`, `$executeRawUnsafe`), paired with `pnpm typecheck` and DI composition smoke tests.
4. **Offline Pure-Domain Testability:** Pure domain calculators and state-machine guards under `src/core/domain/` (`Issue #3`) must remain 100% deterministic and executable offline without a live PostgreSQL database, network socket, or external API—and in-memory test adapters must never be cited as proof that PostgreSQL RLS or SQL triggers work.
5. **Real PostgreSQL `erp_app_user` Verification (`Issue #2+`):** Once `Issue #2` lands, CI and local database verification (`pnpm test:db:rls`) must execute against a real PostgreSQL instance connected as `erp_app_user` (`NOBYPASSRLS`) proving `FORCE ROW LEVEL SECURITY` (including `shared.User`), cross-tenant isolation between `ORG_SALVAGE_EXPORT` and `ORG_CANNABIS_NURSERY_PROC`, immediate `OrganizationMembership.isActive = false` revocation denial, `tx.$queryRaw` transaction-local context isolation across pooled connection reuse, rollback safety, concurrent access, and database `CHECK`/trigger constraints. Do not require PostgreSQL tests for isolated pure TypeScript math (`Issue #3`), and do not fabricate passing test runs when database or application scaffolding does not yet exist.
6. **Strict Cannabis Phase 2B Boundary:** Dormant `cannabis` Prisma models (`Issue #1`) and dormant PostgreSQL RLS/constraints/finalization triggers (`Issue #2`) are permitted in Phase 1A foundation issues. Zero cannabis application services, cannabis UI routes, or Phase 2B `FR-CAN-01`–`04` business workflow test suites may be added to Phase 1A Issues `#1`–`#10`.
