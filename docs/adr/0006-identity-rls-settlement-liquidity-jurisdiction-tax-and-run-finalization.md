# Identity RLS Firewall, Settlement Liquidity Separation, Jurisdiction-Aware GST/HST & Trigger-Gated ProductionRun Finalization

Status: Accepted (Amends and supersedes specific RLS/identity, Prisma raw-query, checkout-settlement, GST/HST rate, dormant `ProductionRun` constraint, and CI no-stub verification clauses in [`ADR-0005`](./0005-rls-pooler-safety-ebay-billing-agent-and-post2025-cannabis.md))

Following a final pre-implementation architecture, PostgreSQL security, Canadian tax, and data-integrity audit, we adopt seven targeted corrections across the specifications and Phase 1A backlog (`Issues #1`–`#10`) while preserving our single modular monolith, two-corporation/separate-site boundary ([`ADR-0004`](./0004-independent-legal-entities-and-physical-site-separation.md)), `"WARN_ONLY"` physical-custody agility ([`ADR-0003`](./0003-ontario-regulatory-audit-warn-only-agility-and-tranched-capital.md)), and strict Phase 2B cannabis code deferral:

1. **Active Membership Schema & Least-Privilege `shared.User` RLS Firewall (`FIX 01` & `FIX 02`):** We add `OrganizationMembership.isActive` (`@default(true)`, paired with `deactivatedAt`, `deactivatedById`, and `revocationReason`) so revoking a membership immediately terminates organization access without breaking historical foreign keys. We place `shared.User` inside `ENABLE` + `FORCE ROW LEVEL SECURITY` (`user_select_self_or_org_comember` and `user_update_self_profile`) and revoke `INSERT`, `DELETE`, `TRUNCATE`, and privileged-column `UPDATE`s on `shared.User` (plus `DELETE`/`TRUNCATE` on `Organization`, `OrganizationMembership`, and append-only audit/financial tables) from `erp_app_user`, preventing salvage-only users from enumerating or mutating unrelated cannabis personnel. Because `set_config('app.current_*', ..., true)` values are not self-authenticating against raw SQL, server-side `auth-context.ts` derives context exclusively from `@supabase/ssr` `await supabase.auth.getUser()` + active `OrganizationMembership` rows, while `SECURITY DEFINER` helpers (`SET search_path = ''`, owned by the `BYPASSRLS` migration owner to prevent RLS recursion) validate that `(app.current_org_id, app.current_user_id, app.current_role)` matches a live `isActive = true` membership, active `User`, and active `Organization` on every query.
2. **Parameterized `tx.$queryRaw` Transaction-Local Context Wrapper (`FIX 03`):** We replace `tx.$executeRaw` around `SELECT set_config(...)` in `withTenantTransaction` and `withAuthBootstrapTransaction` with parameterized `tx.$queryRaw`, immediately followed by an in-transaction `SELECT "shared"."current_org_id"()` assertion that rolls back and throws `TENANT_CONTEXT_UNAUTHORIZED` if membership verification fails, while reusing existing `Prisma.TransactionClient` instances safely on nested calls (rejecting mid-transaction tenant/role mismatches) and separating `DATABASE_URL` (`:6543?pgbouncer=true` as `erp_app_user`) from `DIRECT_URL` (`:5432` migration owner).
3. **Dormant Phase 2B `CannabisProductionRunStatus` & Locking Finalization Triggers (`FIX 04`):** Because a row-level `CHECK` constraint on `cannabis.ProductionRun` cannot aggregate child `ProductionRunInput` / `ProductionRunOutput` rows and blocks inserting a run header prior to child rows, we add `CannabisProductionRunStatus` (`DRAFT | IN_PROGRESS | FINALIZED | VOIDED`) and replace the parent-only mass-balance `CHECK` with a `BEFORE INSERT OR UPDATE` trigger on `ProductionRun` plus `BEFORE INSERT OR UPDATE OR DELETE` child triggers acquiring `SELECT ... FOR UPDATE` on the parent run. Transitioning to `FINALIZED` atomically verifies $\ge 1$ input, $\ge 1$ output, exact child-sum equality with cached parent totals, same-organization integrity, exact tenth-gram mass conservation (`RULE-CAN-001`), and the internal `2.0%` QAP variance gate (requiring `requiresQapVarianceReview = true` and either output `complianceHold = true` or QAP sign-off + reason note—explicitly treated as an internal quality gate, never a statutory Health Canada allowance). Once `FINALIZED` or `VOIDED`, parent and child rows are immutable; post-finalization corrections use auditable compensating `CanonicalInventoryEvent` / reversal-run entries (`reversesProductionRunId`, `reversesCanonicalEventId`). Zero cannabis application code or tests execute in Phase 1A.
4. **Payment Confirmation vs. Bank Settlement Liquidity Separation (`FIX 05`):** We introduce `PaymentSettlementState` (`SALE_RECORDED`, `PAYMENT_INITIATED`, `PAYMENT_CONFIRMED`, `MARKETPLACE_PAYOUT_PENDING`, `BANK_SETTLEMENT_PENDING`, `BANK_SETTLEMENT_CONFIRMED`, `REFUNDED_OR_CHARGED_BACK`) and `CashCustodyState.PENDING_EXTERNAL_RECEIVABLE` (enforced by SQL `CHECK` `sale_settlement_custody_consistency`). Unconfirmed Interac e-Transfers (`BANK_SETTLEMENT_PENDING`), pending eBay Managed Payouts (`MARKETPLACE_PAYOUT_PENDING`), and unswept physical cash (`HELD_IN_OPERATOR_FLOAT`) are tracked separately from confirmed corporate bank deposits (`BANK_SETTLEMENT_CONFIRMED` / `SETTLED_ORIGIN_CORP_BANK`) and are excluded from deployable `AvailableWorkingCapital_CAD` (while pending receivables are also excluded from `DistributableRealizedProfitPool_CAD`), ensuring auction bids and partner draws never spend anticipated cash.
5. **Jurisdiction-Aware CRA Place-of-Supply GST/HST & Verified Fee ITCs (`FIX 06`):** Under `RULE-TAX-HST-01`, `EBAY_MOTORS_SHIPPED` (`MARKETPLACE_FACILITATOR_COLLECTED`) records authoritative marketplace-reported buyer tax in `buyerTaxRemittedByPlatformMinor` (never fabricated from a flat 13% Ontario assumption), sets corporate `taxOrVatMinor = 0`, and promotes seller-fee GST/HST from `estimatedPlatformFeeTaxCadMinor` into `itcReceivableCadMinor` only when backed by verified tax-invoice documentation (`Excise Tax Act` s. 169(4)) for a GST/HST-registered `Organization`. Direct/classified sales (`DIRECT_SELLER_COLLECTED`) apply `13%` Ontario HST on in-Ontario pickups/deliveries, apply configurable CRA destination-province GST/HST rates on seller-shipped Canadian orders (`ON 13%`, `NS 14%` [post-April 1, 2025], `NB/NL/PE 15%`, `AB/BC/MB/SK/QC/YT/NT/NU 5%` federal GST), and apply `0%` (`ZERO_RATED_EXPORT`) strictly on documented seller-exported international shipments, with credit-note tax reversals (`ETA s. 232`) mirrored on refunds.
6. **Fail-Closed Deterministic Verification & Consolidated Governance (`FIX 07` & `FIX 08`):** We replace the negated `! grep` check (which fails open on missing paths or `grep` exit code `2`) with a fail-closed verification script (`scripts/verify-no-stubs.mjs` / `pnpm verify:no-stubs`) combined with TypeScript compilation, module composition smoke tests, offline domain tests, and mandatory real PostgreSQL `erp_app_user` integration tests (`pnpm test:db:rls`), and consolidate our Regulatory & Tax Obligation Register, Requirements-to-Issue Traceability Matrix, Open Business & Site Decisions, and Phase 1A Implementation Frontier into tracked root [`handoff-inventory-phase1a.md`](../../handoff-inventory-phase1a.md) and [`AGENTS.md`](../../AGENTS.md).
